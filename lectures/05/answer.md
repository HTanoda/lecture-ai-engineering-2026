## 宿題

基礎課題として、1ページに根拠がそろう質問で、検索件数を絞っても回答を裏づけられるかを確かめた。

- 質問：「第2回の説明では、LoRAは何を固定し何を学習しますか？ QLoRAは何を加えますか？」
- 変更：`app/config.py` の `RAG_TOP_K` を 5 から 1 に変更した。
- 実行条件：通常のベクトル検索モード、回答モデル `gemini-3.5-flash-lite`、第1〜3回の本講義214ページを収録した同梱DBを使用。索引を作り直さず、各条件で同じ質問を `uv run --frozen python -m app.agent --trace` に渡した。

| traceで確認した項目 | 変更前（5件） | 変更後（1件） |
|---|---|---|
| ツールと回数 | `search_materials` 1回 | `search_materials` 1回 |
| 引数 `query` | `LoRA 固定 学習 QLoRA 加える` | `LoRA QLoRA 固定 学習 第2回` |
| 検索結果の先頭 | 第2回・PDF p.52 | 第2回・PDF p.52 |
| 回答が引用したページ | 第2回・PDF p.51、52 | 第2回・PDF p.52 |

| モデル応答回数 | 2回 | 2回 |
| 生成API推定費用（埋め込み・索引構築分を除く） | 0.001421 USD | 0.000823 USD |

**回答と根拠。** 5件では、LoRAは元の重みを固定して差分を表す二つの小行列を学習し、QLoRAは元の重みを4bitに圧縮してメモリを節約すると回答した。1件でも三つの問いに答え、固定する重みを W、学習する行列を A・B と明示した。引用先のp.52にはこの区別と4bit圧縮が図付きで載っている。5件の回答が追加で引用したp.51でも、本体の固定、小さな追加部分の更新、QLoRAの省メモリ効果を確認できた。

**取得と引用の違い。** traceではツールの返り値が途中で省略されるため、実行後に各条件の検索語・件数で検索だけを再実行した。5件では第2回のp.52、51、60、47、61の順に返り、回答が引用したのは先頭2ページだった。1件ではp.52だけが返った。

**気づきと制約。** 今回は検索1位のp.52に必要な根拠がそろい、1件でも回答の要点を保ったまま入力が1,835トークン減った。一方、根拠が別々のページにある質問でも1件で足りるかは未検証である。各条件の成功は1回ずつで、モデルが選んだ検索語も異なる。1件条件の初回はモデル混雑（503）で回答を取得できず、同じ条件で再試行した。表の時間・使用量・推定費用は成功した実行の値であり、時間差や費用差はこの質問での観測値として扱う。
